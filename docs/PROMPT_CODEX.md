# Codex への指示書 — 高画質版の復元・照合・Release作成（統合版）

あっきーがCodexに**そのまま貼る**ためのプロンプト。
ChatGPT版（Windowsローカルの安全策）と Claude版（リポジトリのスクリプト活用＋後工程）を統合したもの。

**2フェーズ構成**：
- フェーズ1：復元と照合まで。**終わったら必ず停止して報告**
- フェーズ2：あっきーが結果を確認して「フェーズ2進めて」と言ったときだけ、Release作成〜記録更新

## 前提

- Codex が **drive.google.com と github.com に接続できる**こと（Windows PC のローカル実行を想定）
- 作業ディスクに **1.5GB 以上**の空きがあること
- GitHub のログインが必要になったら、Codex はあっきーに操作を渡すこと（パスワードをチャットで扱わない）

## 絶対に守るルール（全フェーズ共通）
1. 動画・音声の再エンコード、変換、圧縮、音量調整、メタデータ変更を一切しない。
   ffmpeg のインストール・使用も不要なので行わない（復元は単純なバイナリ結合のみ）
2. SHA-256 が一致しないファイルは、結合にも Release にも使わない
3. 作業は専用フォルダ内だけで行う。既存ファイルの削除・上書き・移動はしない。
   同名ファイルが既に存在する場合は停止して報告する
4. ダウンロードに認証・確認操作が必要な場合や、正しいバイナリを取得できない場合は、
   別のファイルで代用せず停止して報告する
5. MP4 や .bin を git にコミットしない（.gitignore で弾かれるが、-f で入れない）
6. 「放課後トークルーム_1時間_スマホDrive版.mp4」（HEVC・約101.6MB）は低画質版。一切使わない
7. GitHub のログインが必要になったら、自分で認証情報を扱わず、ユーザーに操作を渡す
8. 想定外の状況では、回避策を自作せず停止して報告する

### 1-1. リポジトリを取得
git clone https://github.com/manabi-ai-lab/manabi-bgm

docs/RESTORE.md を読む（8パーツの Drive ファイルID・期待サイズ・期待ハッシュの表がある）。

### 1-2. 専用フォルダを作る
リポジトリ内に after-school-talk-room\high-quality-restore を作成し、
以降のダウンロード・結合はすべてこの中だけで行う。

### 1-3. Drive からダウンロード
公開フォルダ（リンクを知っていれば認証不要）:
https://drive.google.com/drive/folders/1BwpEpgVjfd5aLJRp1fL8SwKiKnxt-Hpp

次の8ファイルを専用フォルダにダウンロードする。
after-school-talk-room-one-hour-youtube.part-00.bin 〜 part-07.bin

各ファイルの個別リンクは docs/RESTORE.md の表を使ってよい。
期待サイズ：part-00〜06 は各 94,371,840 バイト、part-07 は 19,324,024 バイト。
サイズが一致しないファイルはダウンロード失敗なので、そのファイルだけ取り直す。

補助ファイル（README_復元方法.txt / restore-windows.bat / ORIGINAL_SHA256.txt /
PARTS_SHA256.txt）は Drive から取ってもよいが、同じものがリポジトリの
tracks/after-school-talk-room/backup/ に検証済みで入っているので、そちらを使ってよい。

### 1-4. パーツ個別の照合（結合前に必ず）
PowerShell の場合：
  Get-FileHash -Algorithm SHA256 で8個すべてを計算し、
  tracks/after-school-talk-room/backup/PARTS_SHA256.txt の値と照合する。
bash が使える場合：
  sh ../../scripts/restore-and-verify.sh を専用フォルダ内で実行すれば、
  パーツ照合→結合→最終照合まで自動で行う（1-5・1-6 も兼ねる）。

1個でも一致しない場合は結合せず停止し、どのパーツが不一致かを報告する。

### 1-5. 結合（8個すべて一致した場合のみ）
restore-windows.bat を実行するか、copy /b で part-00 から part-07 を番号順に
バイナリ結合する。
復元後のファイル名：放課後トークルーム_1時間_高画質版.mp4

### 1-6. 最終検証
復元したMP4について確認する。
  期待サイズ  : 679,926,904 バイト
  期待SHA-256 : 118de0f31bca5de2386e4099df674d67cc40a59dbf9ddf11443b887211605cfc
完全一致しなかった場合は docs/RESTORE.md の「4. 一致しなかったとき」に従い、
原因のパーツを特定して報告する。再エンコードでのごまかしは絶対にしない。

### 1-7. フェーズ1の報告（ここで停止）

## フェーズの合間にあっきーがやること

- フェーズ1の報告を見て、**サイズとSHA-256が期待値に完全一致**していることを確認
  → 一致していたら「フェーズ2進めて」とCodexに言う
  → 不一致なら、報告をそのままClaudeに貼る（原因の切り分けを手伝います）
- フェーズ2の途中で `gh auth login` を求められたら、ブラウザでログイン操作
- フェーズ2完了後：Releaseページをスマホで開いてMP4がタップ再生できるか確認
  → その後 YouTube 限定公開投稿へ（`docs/YOUTUBE.md`。ログインが要るのであっきーの作業）

## うまくいかないときの切り分け

| 症状 | 原因と対応 |
| --- | --- |
| Drive からダウンロードできない | Codex の実行環境にネットワーク制限。あっきーがブラウザで8ファイルを専用フォルダへ手動ダウンロードし、1-4 から再開させる |
| パーツのハッシュ不一致 | ダウンロード失敗。該当パーツだけ取り直し |
| 同名ファイルが既にある | 過去の作業の残骸の可能性。中身を確認するまでCodexには触らせない設計。あっきーが確認して指示 |
| gh auth でエラー | あっきーがブラウザでログイン操作。パスワードはCodexに渡さない |
| Release 作成が 403 | その GitHub アカウントに manabi-ai-lab への write 権限がない。あっきーのアカウントで gh にログインし直す |
